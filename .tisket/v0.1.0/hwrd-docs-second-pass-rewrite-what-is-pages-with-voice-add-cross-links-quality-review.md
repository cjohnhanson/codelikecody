The first pass docs are factually correct and structurally sound but read
like they were generated. This pass focuses on making them good to read.

## What needs work

1. **what-is-codelikecody.md** — reads like a source code walkthrough, not
   something written by a person who built the thing and cares about it.
   Needs the author's voice. This is the most important doc.

2. **what-is-tisket.md** — same problem. Correct but lifeless.

3. **what-is-missouri.md** — same.

4. **Cross-linking** — concepts are mentioned across docs without links.
   First-mention linking pass needed on every doc.

5. **Getting started tutorials** — mechanically correct but feel like
   command transcripts in places. Need to show what the reader sees
   (expected output) and explain why each step matters.

## Process

Use the documentation-writing skill's nested review loops:
- Inner loop per doc: rewrite → fresh-eyes quality review → fix → repeat
- Outer loop: site coherence review → cross-linking pass → fix
- Separate quality evaluators from accuracy evaluators

## Done when

- Fresh-eyes reviewers say the writing sounds human, not generated
- Every concept mention links to its explanation on first use
- Site coherence review finds no dead ends or missing links
